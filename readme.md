LAAS-LAPLACE Hackathon Test Bench
==================================

This repository contains the code for the LAAS-LAPLACE Hackathon Test Bench. The test bench is composed of digital multimeters, an oscilloscope, a power supply, a device under test (DUT: two half bridges in opposition) and a PWM generator (SPIN Board).

This project started as a 2-day HACKATHON at LAAS+LAPLACE (Apr. 2024), then followed by monthly open science sessions, a.k.a open power tuesday.

Description
------------
(This part is a work in progress - must be updated)

A supervisor has been written `Supervisor_script.py` which will do the test sequence:
1) Config microcontroller and turn ON gate signal
2) Start logging DC current at DMM
3) Sweep DC bus Voltage (ramp up)
4) Sweep Phase Shift generated by microcontroller (ramp up and down)
5) Ramp down DC bus Voltage
6) Read Buffer of DMM
7) Plot and export data in .csv with timestamp
8) Return to initial state


The project is started by interface.py

Phase shift is written by `Opposition_GenerateJson_v1_4.py` as float degrees (2 decimals) and swept as floats by the supervisor (since Nov. 2026).
`PhaseInit` is the first current step: one LEG2 write, one scope frame per current (the 26 Nov lead-in point was removed on 27 Nov).
Until the SPIN firmware accepts float degrees (ticket #7), the firmware truncates the phase to an integer degree.
Both scripts take an optional base-config path: `python3 Opposition_GenerateJson_v1_4.py path/to/base-config.json`, same for `supervisor_script.py`.
Run the unit tests (no hardware needed) with `python3 -m unittest discover -s tests`.


Talking ThingSet to the SPIN (since Nov. 2026)
------------

The supervisor speaks either the old string protocol (`comm_protocol/`) or ThingSet, chosen by the base config:

```json
"shield_protocol": "thingset",
"shield_vid": 12259,
"shield_pid": 256,
"DeadTimeComp": 0
```

* `shield_protocol`: `"string"` (default when the key is missing, old firmware, PID 257 = 0x0101) or `"thingset"`
  (ThingSet bench firmware, OwnTech Core `serial_thingset_example_modular` lineage, PID 256 = 0x0100, product `SPIN`).
  The session configs under `sessions/2026-11-27/` use `"thingset"`.
* `DeadTimeComp`: `0`/`1`, dead-time duty compensation off/on, written to `Config/wDeadTimeComp` during setup
  (ThingSet only; leave it out for the string firmware).
* Optional: `shield_port` (an explicit port, e.g. `/dev/serial/by-id/usb-OwnTech_Technologies_SPIN_<serial>-if02`),
  `shield_serial` (picks one board when several SPINs are plugged in), `shield_verify` (default `true`: read back every write).

`lib/thingset_shield.py` (`ThingSetShield`) keeps the `sendCommand(action, *args, delay=...)` interface, so
`supervisor_script.py` is unchanged. Each action becomes one ThingSet write, read back to catch values the firmware
silently restores; errors raise. `PHASE_SHIFT` writes the float `Config/LegN/wPhaseShift_deg`. The shim rejects phases
outside 0–360° and dead times outside 100–2000 ns before sending. `lib/thingset_tools.py` is the transport, vendored
from OwnTech Core.

The SPIN shows two serial ports with the same VID/PID: `if00` (console, scope data) and `if02` (ThingSet shell).
The supervisor picks `if02` through `/dev/serial/by-id/*-if02`, then by USB interface number, then by a handshake
probe at 115200 baud. **Never open `if00` at 1200 baud**: that reboots the board into its bootloader. With two SPINs
attached, set `shield_serial`. Manual check: `python3 lib/thingset_tools.py --port /dev/serial/by-id/...-if02` dumps
the object tree.


Requirements
------------

* Python 3.x
* PyVISA
* pandas
* matplotlib

SPIN board must be loaded with v1.0.0-rc-power_tuesday branch
* The python files with key functions for SPIN must be copied in the "comm_protocol" folder
* > The folder is located in the cloned GIT repo. at owntech\lib\USB\comm_protocol
* > The folder is also provided here in `comm_protocol`
* The DMM used is SDM3065 from Siglent
* The power supply used is Z650+ from TDK Lambda
* Use any other equipment and adapt the SCPI commands, if needed
* Do not forget to add the address of DMM and powersupply!!!! Can use def `list_instruments()`: if needed


Getting Started
---------------

1. Clone the repository to your local machine:
```bash
git clone https://github.com/your_username/laas-laplace-hackathon.git
```
2. Install the required packages:
```bash
pip install -r requirements.txt
```
3. Connect your instruments to your computer and make sure they are recognized by PyVISA:
```bash
python -m pyvisa.info
```
4. Run the `interface.py` script:
```bash
python interface.py
```
or 
```bash
python main.py
```
Instruments
------------

### Digital Multimeters

The digital multimeters are used to measure the voltage, current and temperature of the DUT. The `measure_devices_init()` function initializes the multimeters and checks their identity.

### Power Supply

The power supply is used to provide power to the DUT. The `supply_init()` function initializes the power supply and sets up the channels.

### Oscilloscope

The oscilloscope is used to visualize the waveforms of the DUT. The `Oscilloscope` class provides methods to configure the scope, acquire data and save it to a CSV file.

### Device Under Test (DUT)

The DUT is the device being tested in the LAAS-LAPLACE Hackathon. The `Twist_Device` class provides methods to control the DUT and acquire data.
